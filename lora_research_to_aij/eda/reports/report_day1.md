## Шаг 2. Таблица BFCWE: дособорка DAT из SVG-графов

**Проблема.** Первичная таблица `bfcwe.csv` (194 CWE) собрана из markdown-страниц NIST
(`usnistgov/BF`): MEM и INP полные, DAT — только 13 id из прозы (полный список ~84 живёт
в SVG, недоступном для выкачивания извне).

**Решение.** Локальный grep по склонированному репозиторию `raw_data/BF/static/images/CWE2BF/`,
результат передан сюда и сверен.

**Верификация (что проверено):**
1. Структура графов корректна: все parent-связи существуют, «ромбы» (CWE с двумя
   родителями) — норма CWE-иерархий; косметический дефект нумерации level в G2.
2. Сверка с официальными markdown-списками: почти полное покрытие; расхождения
   (590, 94, 97, 98, 1336) объяснены обрезкой вставки — закрыты объединением.
3. DAT = 84 уникальных CWE — точное совпадение с официальным заявлением «84 data type CWEs».
4. Все 13 «prose»-id из черновика подтверждены графами.

**Результат:** `bfcwe_final.csv` — 297 уникальных CWE (INP 152, DAT 76, MEM 66, мультифазные 11;
колонки: cwe, phase, graphs, category, abstraction, relation, source).
Эффект: отсечение «вне BFCWE» сократилось 4 771 → 3 269; вернулись CWE-20 (×1100), CWE-190 (×310).

## Шаг 5. Дедупликация

Ноутбук `dedup_bigvul.ipynb`:
1. Сильная нормализация: идентификаторы → `v0,v1,..` (rename-only дубликаты становятся точными),
   числа → `N`, строки → `S`;
2. MinHash (100 пермьютов, LSH 25×4) + точная верификация Jaccard ≥ 0,7;
3. Кластер = одна метка CWE (большинство голосов, конфликты считаются), один сплит
   (большинство, ничья → train), представитель — самый длинный член с финальной меткой;
   утечка train/test = 0 по построению;
4. Отсечение классов <15 примеров — после дедупа.

**Выход:** `data/processed/dedup_final.csv` (по строке на кластер).

**Итоги прогона (после исправления бага сплитов):**
- 4 234 кластера (топ размеров: 26, 9, 8, 8, 8; синглтонов 3 317);
- rename-insensitive точных дубликатов: 1 076; near-dup пар (0.7 ≤ j < 0.999): 565;
- конфликтных кластеров (разные метки CWE у членов): 90 / 4 234 (2,1%) → выброшены
  (95 строк), полный список в `data/processed/dedup_conflicts.csv` на ручной разбор;
  типичный пример: побайтово идентичная функция (yara, j=1.00) с метками 125 vs 416;
- **классов: 15 (было 32 до отсечения <15) | строк: 4 063**;
- распределение: CWE-119 ×1625 (40%), CWE-20 ×833 (20.5%), далее 125/416/190/476/787…;
  фазовый профиль: MEM ~71%, INP ~22%, DAT ~7%;
- баг первого прогона (синглтоны и единогласные кластеры падали в train, test
  обнулялся) найден по сводке сплитов и исправлен; утечка train/test после починки: 0.

**Открыто на разбор:** глазами проверить 26-членный кластер и топ конфликтов;
строка сплитов после исправления — вписать сюда.
